# 技术演进路径：B（Markdig AST + 语法/渲染分离）→ C（语义文档模型）

> 决策：**现阶段全力投入 B 方案**；B 完成后，在 B 的语法服务与渲染抽象之上演进 C，不重写。
>
> 实施状态（2026-11-08）：**B0–B5 主体落地，但尚未完全闭环**；见 [B 阶段实施记录](33-B阶段实施记录.md) 的完整性审计。PublicAPI baseline、Trim/AOT、性能基线已完成，见 [B 阶段基线](34-B阶段基线-API-Trim-性能.md)；Syntax-only 诊断、安全下沉、Markdig 节点子集、块级增量已完成；真实 Arc 集成与 CI 自动化仍待补。
> 关联：[语法与渲染分离讨论](31-语法与渲染分离讨论.md)、[ADR-0011 Markdig AST 直连渲染](adr/0011-markdig-ast-direct-to-avalonia.md)、[ADR-0020 1.0 不引入 IR](adr/0020-no-ir-in-1.0.md)。

## 1. 目标与边界

### 1.1 B 阶段目标

1. 新增 **`PuraMarkdown.Syntax`**：只依赖 Markdig，不依赖 Avalonia，提供解析、语法树、诊断、大纲、流式扫描。
2. **`PuraMarkdown`（Avalonia 渲染）** 只消费 Syntax 产出的 `PuraDocument`/Markdig AST，不再自己解析。
3. 渲染层提供稳定的 **`IPuraNodeRenderer`**，Arc.Avalonia 可基于 Markdig AST 自定义控件/样式。
4. 现有宿主 API（`PuraMarkdownView`/`PuraMarkdownOptions`/`PipelineBuilder`）保持可用，内部迁移。
5. 性能不退化；流式/虚拟化/Agent/Chat 行为不回退。

### 1.2 B 阶段不做

- 不引入自定义语义节点模型（C 的内容）；
- 不做进程外/JSON-RPC 协议；
- 不替换 Markdig；
- 不要求 Arc 完全脱离 Markdig（B 的契约就是 Markdig AST）。

### 1.3 C 阶段触发条件

B 完成后，出现以下任一条件才启动 C：

- Arc 或其它渲染器不能依赖 Markdig；
- 需要跨进程/跨语言文档协议或稳定序列化；
- 需要替换 Markdig/支持非 Markdig 解析器；
- 插件生态要求与 Markdig 无关的统一节点 schema；
- Markdig 大版本升级导致 B 的兼容策略失效。

## 2. B 目标架构

```text
┌──────────────────────────────┐
│ PuraMarkdown.Syntax          │  Markdig + Pura 旁路信息
│  PuraSyntaxBuilder           │
│  PuraSyntaxPipeline          │
│  PuraDocument                │  MarkdownDocument + Diagnostics + Outline + Version
│  PuraDiagnostic / PuraOutline│
│  PuraSyntaxStreamingSession  │  稳定边界/尾部窗口/块扫描
└──────────────┬───────────────┘
               │ MarkdownDocument / PuraDocument
┌──────────────▼───────────────┐
│ PuraMarkdown（Avalonia）      │
│  PuraDocumentView / View     │
│  IPuraNodeRenderer           │  MarkdownObject → Control
│  默认渲染器/主题/虚拟化       │
│  PuraPipelineBuilder         │  组合 Syntax + Renderers
└──────────────┬───────────────┘
               │ Avalonia Control
┌──────────────▼───────────────┐
│ Arc.Avalonia                 │
│  自定义节点→控件映射、样式     │
└──────────────────────────────┘
```

### 2.1 Syntax 公共契约

```csharp
namespace PuraMarkdown.Syntax;

public sealed class PuraSyntaxBuilder
{
    public PuraSyntaxBuilder UseCommonMark();
    public PuraSyntaxBuilder UseGfm();
    public PuraSyntaxBuilder UseMarkdownExtension(IMarkdownExtension extension);
    public PuraSyntaxBuilder UseSanitizer(IAstSanitizer sanitizer);
    public PuraSyntaxBuilder ConfigureLimits(Action<PuraLimits> configure);
    public PuraSyntaxPipeline Build();
}

public sealed class PuraSyntaxPipeline
{
    public MarkdownPipeline MarkdownPipeline { get; }
    public PuraDocument ParseDocument(string markdown, int version = 0);
    public MarkdownDocument Parse(string markdown);
}

public sealed record PuraDocument(
    int Version,
    string Text,
    MarkdownDocument Markdown,
    IReadOnlyList<PuraDiagnostic> Diagnostics,
    PuraOutline Outline);

public sealed record PuraDiagnostic(
    string Code,
    PuraDiagnosticSeverity Severity,
    string Message,
    SourceSpan Span,
    string? NodeType = null);

public sealed record PuraOutline(
    IReadOnlyList<PuraHeading> Headings,
    IReadOnlyList<PuraFoldRange> Folds);
```

- `MarkdownDocument` 就是语法树，不复制节点；
- `PuraDocument` 是**旁路元数据**（诊断/大纲/版本/源文本），不是第二棵树；
- `PuraDiagnostic` 对应 LSP diagnostics；`Code` 使用 `PURA-*`；
- `PuraOutline` 供 IDE 式大纲/折叠使用，不依赖 Avalonia。

### 2.2 渲染公共契约

```csharp
namespace PuraMarkdown.Rendering;

public interface IPuraNodeRenderer
{
    bool CanRender(MarkdownObject node, PuraRenderContext context);
    Control Render(MarkdownObject node, PuraRenderContext context);
}

public sealed class PuraDocumentView : ContentControl
{
    public PuraDocument? Document { get; set; }
    public PuraMarkdownOptions? Options { get; set; }
    public event EventHandler<PuraInteractionEventArgs>? InteractionOccurred;
    public event EventHandler<PuraWarningEventArgs>? Warning;
    public event EventHandler<PuraLinkClickedEventArgs>? LinkClicked;
    public event EventHandler<PuraImageEventArgs>? ImageLoading;
    public event EventHandler<PuraImageLoadedEventArgs>? ImageLoaded;
}
```

- `PuraDocumentView` 绑定 `PuraDocument` 渲染；
- `PuraMarkdownView` 保留为默认宿主（Markdown 文本 + 流式 + 便捷 API），内部委托 `PuraDocumentView`；
- Arc 可以直接用 `PuraDocumentView` + 自定义 `IPuraNodeRenderer`，或只消费 Syntax 自己实现控件树。

### 2.3 PipelineBuilder 兼容

```csharp
// 宿主原有用法保持
var pipeline = new PuraPipelineBuilder()
    .UseCommonMark()
    .UseGfm()
    .UseCodeHighlighter(new ColorCodeHighlighter())
    .Build();

// 新增 Syntax 入口
var syntax = new PuraSyntaxBuilder()
    .UseCommonMark()
    .UseGfm()
    .Build();

var doc = syntax.ParseDocument(markdown);
```

`PuraPipelineBuilder` 内部持有 `PuraSyntaxBuilder`/`PuraSyntaxPipeline`；`PuraPipeline` 暴露 `Syntax` 属性。

## 3. B 工作包与验收

### B0：基线与契约冻结（S）

- 输出：
  - 本演进文档 + ADR-0025（Syntax/Renderer separation）；
  - 当前性能/测试基线（1MB/1000 块、消息虚拟化、流式）；
  - 类型分层清单（Syntax vs Rendering）。
- 验收：
  - 明确 `PuraDocument`/`IPuraNodeRenderer` 公共面；
  - 确认 Markdig 版本锁定策略与支持节点子集。

### B1：抽出 `PuraMarkdown.Syntax`（M）

- 迁移：
  - `MarkdownPipelineBuilder` 配置、`UseCommonMark/UseGfm/UseMarkdownExtension`；
  - `IAstSanitizer`/`DefaultAstSanitizer`、`PuraLimits`、`IUrlPolicy`；
  - `StreamingBlockScanner`；
  - 诊断/大纲生成（从 `PuraMarkdownView` 中抽出）。
- 新增：
  - `PuraSyntaxBuilder`、`PuraSyntaxPipeline`、`PuraDocument`、`PuraDiagnostic`、`PuraOutline`；
  - `PuraSyntaxStreamingSession`（流式语法会话）。
- 验收：
  - Syntax 项目**无 Avalonia 引用**；
  - 解析/诊断/大纲/流式测试独立运行；
  - 与旧解析结果逐块/逐行一致。

### B2：渲染层消费 PuraDocument（M/L）

- 迁移：
  - `PuraMarkdownView` 的解析/流式扫描改调 Syntax；
  - 抽出 `PuraDocumentView`；`PuraMarkdownView` 变薄宿主；
  - `IPuraNodeRenderer` 成为渲染入口（`IPuraRenderer` 兼容别名）；
  - `RenderContext` 只保留渲染相关。
- 验收：
  - 全部 golden/渲染/交互测试通过；
  - `PuraMarkdownView` 公共 API 无破坏（alpha 允许少量调整）；
  - Arc 示例：只用 Syntax + 自定义 renderer 渲染标题/段落。

### B3：流式与增量迁移（L）

- 迁移：
  - `PuraStreamingSession` 拆为 Syntax streaming + UI streaming；
  - 稳定边界/尾部窗口/块复用归属 Syntax；
  - 渲染层只处理节点新增/替换/移除。
- 验收：
  - 流式增量/重复提交/中断/异步测试等价；
  - 1MB/1000 块性能在基线范围内；
  - 代码块/表格/Agent fence 无重复/截断回归。

### B4：Arc.Avalonia 集成验证（M）

- 输出：
  - 示例：Arc 风格渲染器（自定义标题/代码块/表格控件）；
  - 文档：如何只引用 `PuraMarkdown.Syntax`、如何注册 renderer；
  - 边界说明：Arc 负责 UI，Pura 负责解析/诊断/流式。
- 验收：
  - 不继承 `PuraMarkdownView` 也能渲染 `PuraDocument`；
  - 样式/控件可完全自定义；
  - 语法诊断/大纲可用于 Arc 工具栏。

### B5：硬化与 B 退出门（M）

- 性能基准、AOT/Trim、包元数据、API baseline；
- 文档：Syntax API 参考、迁移指南；
- 代码质量：无 Avalonia 泄漏到 Syntax、无 Markdig 泄漏到 Chat 模型（可选）。
- B 退出标准：
  1. Syntax 包独立可用且无 Avalonia；
  2. 默认渲染路径性能不退化（阈值：解析/首屏 ≤ +5%，内存 ≤ +10%，以基线为准）；
  3. 全部测试/golden 通过；
  4. Arc 示例可运行；
  5. 公共 API 文档与迁移指南完成。

## 4. B 完成后的 C 演进

C 不重写 B；在 B 的 `PuraDocument`、`IPuraNodeRenderer`、SyntaxService 上增量演进。

### C1：语义节点模型（L）

- 新增 `PuraSemanticDocument`/`PuraSemanticNode`，先作为 `PuraDocument.Semantic` 可选旁路；
- 只覆盖 B 的“支持节点子集”；
- Markdig AST 仍保留，作为兼容/回退。

### C2：双读路径与转换（L）

- `PuraSemanticDocumentBuilder` 从 Markdig AST 构建语义节点；
- 性能基准；若超预算，使用惰性/池化；
- 新增 `IPuraSemanticNodeRenderer`（输入 `PuraSemanticNode`）。

### C3：默认渲染器迁移（L）

- 默认渲染器逐类迁移到语义节点；
- Markdig AST 路径保留为 `Legacy` 适配器；
- Arc 可先用语义节点，不依赖 Markdig。

### C4：C 转正（M）

- `PuraDocument.Semantic` 成为默认；
- Markdig 只在 Syntax 内部；
- 旧 `IPuraNodeRenderer` 标记 `[Obsolete]`，保留一个版本；
- 可选：语义文档 JSON/进程外协议。

### C 退出标准

- Arc 只依赖 `PuraMarkdown.Syntax` + 语义节点，不依赖 Markdig；
- 性能在预算内；
- B 的 renderer/宿主有兼容迁移路径；
- 语义节点 schema 版本化。

## 5. 关键设计决策（B）

1. **Markdig AST 是 B 的语法契约**；`PuraDocument` 只加旁路信息，不复制节点。
2. **Syntax 包零 Avalonia**；Rendering 包零 Markdig 解析逻辑（只消耗 AST）。
3. **`IPuraNodeRenderer` 输入 `MarkdownObject`**，Arc 直接使用 Markdig 类型。
4. **支持节点子集 + Markdig 版本锁定**，不承诺 Markdig 全部 API。
5. **`PuraMarkdownView` 保持默认宿主**；新增 `PuraDocumentView` 供 Arc 组合。
6. **流式扫描归 Syntax**；渲染只消费稳定文档。
7. **C 通过可选 `Semantic` 旁路接入**，不破坏 B 消费者。

## 6. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| Syntax/Rendering 循环依赖 | 限界上下文：Syntax 只依赖 Markdig；Rendering 依赖 Syntax；禁止反向引用 |
| 公共 API 拆分破坏宿主 | 保留命名空间/类型名；兼容包装 `PuraPipelineBuilder`；alpha 阶段明确迁移 |
| 流式迁移回归 | 先抽 `StreamingBlockScanner` + 契约测试，再改 view |
| 性能下降 | B 不引入 AST 转换；逐阶段基准门禁 |
| Markdig 版本升级 | 锁定版本 + 支持子集 + golden/渲染全量测试 |
| Agent/Chat 受影响 | B 先不动 Agent/Chat 行为，只改其依赖的渲染/语法入口；B4 后再分层 |
| C 双模型漂移 | C 早期让语义模型**从 Markdig AST 单向生成**，Markdig 是唯一真源；C4 后再反转 |
