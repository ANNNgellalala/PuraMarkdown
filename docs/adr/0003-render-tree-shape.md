# ADR-0003：渲染树使用固定语义元素枚举 + 组件宿主节点

- 状态：**被 ADR-0011 取代**（2026-11-05：取消 RenderNode 虚拟树，直接产出 Avalonia 控件）
- 日期：2026-11-04

## 背景

IR 需要转成适配器可消费的渲染树。候选：

1. 适配器直接消费 IR；
2. 渲染树 = 自由字符串元素（类似 React `type: string` + props）；
3. 渲染树 = 固定语义元素枚举 + 组件宿主节点（`ComponentRenderNode`）。

## 决策

采用方案 3。

## 理由

- **直接消费 IR**：每个适配器都要重复实现"IR → 平台控件"的全部映射与降级逻辑，新增平台成本高、行为易漂移。
- **自由字符串元素**：适配器需要维护大量字符串→控件的映射表，拼写错误只能在运行时暴露；降级矩阵无法静态检查。
- **固定枚举**（约 25 个语义元素）：映射一一对应、可穷举测试、能力降级可静态验证；扩展组件通过 `ComponentRenderNode` 走组件通道，不污染核心枚举。

## 后果

- 核心新增语义元素属于破坏性变更（需 SemVer 主版本），因此元素集合从 M1 起保持稳定。
- 第三方新组件若需要全新视觉语义，必须实现 `IComponentRenderer`（适配器侧），而不是请求核心加枚举 —— 这正是"可插拔"的边界。
