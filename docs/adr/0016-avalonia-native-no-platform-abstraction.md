# ADR-0016：1.0 只交付 Avalonia 原生控件，多平台后置

- 状态：已接受（取代 ADR-0008）
- 日期：2026-11-05
- 关联：需求 NG-6、架构 §2/§15

## 背景

v0.2 的目标是"核心零 UI 依赖 + 多平台适配器"，并已决定 Avalonia 优先。新需求方案明确 PuraMarkdown 是 Avalonia 控件（渲染器返回 `Control`），且只读桌面场景不需要多平台抽象。

## 决策

1. **1.0 是 Avalonia 原生控件**：核心包直接引用 Avalonia 12.1.5，插件契约直接使用 Avalonia 类型。
2. **不做平台抽象层**：没有 `IAdapter`/`RenderNode`/平台回调。
3. 多平台（Blazor/WPF/MAUI）**不在 1.0 范围**；若未来需要，另立 ADR 做契约抽取。

## 理由

- 用户明确要求 Avalonia 桌面优先（ADR-0008 的结论延续），且新需求方案的四层架构以 Avalonia 为输出。
- 只读单平台下，平台抽象的收益（换 UI 栈）远小于成本（多一层映射、插件要学两套类型、测试矩阵翻倍）。
- 直连 Avalonia 让插件能力最大化（可用任意 Avalonia 控件、动画、自定义绘制），这在"图表/高亮/媒体"场景很重要。
- 包结构与依赖更简单（一个核心包而不是 Abstractions/Core/Rendering/Adapters 四包）。

## 后果

- 未来若需 Web/多平台：需在 `IPuraRenderer` 之上抽"平台无关渲染描述"，并重写默认渲染器；预计 3–4 周（见 ADR-0011 备选）。
- 核心包依赖 Avalonia，无法在无 UI 环境（纯控制台/服务端）中使用；服务端渲染需求需另做方案。
- 测试必须使用 Avalonia 无头环境（`Avalonia.Headless.XUnit`），不能纯单元测试控件。

## 备选

若 2.0 需要多平台，可引入"语义渲染描述 + 平台适配器"，从现有渲染器抽取；本 ADR 不阻止该演进，只声明 1.0 不做。
