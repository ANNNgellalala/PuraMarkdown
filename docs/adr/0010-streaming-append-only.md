# ADR-0010：流式输入只接受 append，不提供编辑与重写

- 状态：已接受（用户决策，2026-11-05）
- 日期：2026-11-05
- 关联：架构 §7、需求 FR-601/FR-607

## 背景

流式场景下，库的输入 API 有几种可能：

1. append-only：只能追加增量，完成后关闭；
2. 允许重写/替换（如"重新生成"时整段替换）；
3. 允许随机编辑（定位修改某一段）。

## 决策

**1.0 只接受 append-only 流式输入：**

```csharp
var session = view.BeginDocument(new PuraDocumentOptions { DocumentId = "msg_42" });
session.Append(delta);        // 任意线程、可高频
await session.CompleteAsync();// 结束该文档（终态）
// 注意：没有 Rewrite/Replace/Edit/Resume API
```

- 一条消息 = 一个文档；消息被"重新生成"时，宿主创建**新文档**（新 `DocumentId`），而不是就地重写。
- `Abort` 语义收敛为"停止接收"：已渲染内容保留，文档进入 `Partial` 终态；**不支持之后续写**。
- 交互组件在 `Complete()` 前默认禁用（与语法规范 §6 一致）。

## 理由

- 与"只读渲染 + 流式输出"的产品定位一致，避免引入编辑态、撤销栈、diff-merge 等复杂度。
- 取消重写/续写后，流式状态机只有 `Created → Appending → Completed/Partial` 三态，稳定 ID 与增量渲染的正确性论证大幅简化。
- "重新生成"本质上是一条新消息，交给宿主用新文档表达，语义更清晰，也不会与 Agent 侧的会话记录冲突。

## 后果

- 需求 FR-601/FR-607 中"续写策略可配置"删除；`Abort` 不再可恢复。
- 宿主若需要"编辑后重发"，自行创建新文档并把编辑内容作为新消息发送（库不参与编辑 UI）。
- 渲染会话与文档一一对应，`DocumentId` 稳定；交互事件的 `documentId` 可直接关联消息。
- 后续如需重写能力，需新增 ADR 并证明增量 diff 在重写场景下的正确性。

## 备选

方案 2（允许整段替换）可作为 2.0 特性：实现代价是引入"文档版本 + 全量重规划"，与当前增量 patch 架构有一定冲突，故 1.0 不做。
