# ADR-0009：1.0 不渲染 HTML、不提供 HTML 子集

- 状态：已接受（用户决策，2026-11-05）
- 日期：2026-11-05
- 关联：需求 FR-701/FR-705、语法规范 §9

## 背景

Agent 输出可能包含原始 HTML。候选：

1. 完全禁用（按文本展示）；
2. 白名单子集（`b/i/code/sub/sup/kbd/br` 等）+ 清洗后转 IR；
3. 放行原始 HTML（由宿主消毒）。

## 决策

**1.0 只处理 Markdown 标准语法与 Pura 扩展语法，不渲染原始 HTML，也不提供 HTML 子集。**

- `HtmlPolicy` 在 1.0 只有 `Disabled` 一个有效值；
- `HtmlBlock`/`HtmlInline` 按**转义文本**展示（保留信息，绝不执行）；
- 不引入 HTML 清洗器，不实现 Permissive 安全等级（等级枚举保留，1.0 仅实现 Strict/Standard）。

## 理由

- 安全面最小：没有 HTML 解析/消毒代码，就没有相应的绕过风险。
- 与"只读、可移植、可测试"目标一致：HTML 无法跨平台映射到 Avalonia 控件树。
- Agent 场景中原始 HTML 少见；若出现，按文本展示反而更符合"看模型原始输出"的预期。
- 减少 1.0 工作量与验收项（安全用例集更小、确定性强）。

## 后果

- 需求 FR-701 简化为"不渲染 HTML"；FR-705 的 Permissive 等级不实现（文档标注"预留"）。
- 若用户明确需要富 HTML（如 Agent 生成 `<details>` 折叠、`<kbd>`），作为 2.0 的独立特性评估，需先定义威胁模型与清洗规则。
- 导出 HTML 时，原始 HTML 同样转义（导出产物安全）。

## 备选

白名单子集（方案 2）保留为 2.0 候选；若实施，必须先有 HTML 语料、清洗器测试与 XSS 回归集。
