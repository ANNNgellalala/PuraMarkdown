# ADR-0006：交互结果只产出事件与建议文本，不内置任何传输协议

- 状态：已接受
- 日期：2026-11-04

## 背景

交互卡片提交后，需要把用户选择"送回 Agent"。候选：

1. 库内置 HTTP/WebSocket 客户端，直接调用 Agent API；
2. 库内置某一种 Agent UI 协议（AG-UI / MCP UI / OpenAI Apps SDK）；
3. 库只产出结构化事件 + 建议消息文本，由宿主实现传输与协议；
4. 库不产出事件，只把选择写回 Markdown 文本。

## 决策

采用方案 3，并以方案 4 的文本形态作为便利输出（`ToUserMessage()`）。

## 理由

- **传输属于宿主**：Agent 连接方式、鉴权、重试、消息队列、会话管理千差万别；库若内置会成为集成瓶颈。
- **协议仍在演进**：AG-UI、MCP Apps 等标准尚未稳定；绑定单一协议等于替用户做长期承诺。
- **可测试性**：纯事件模型可以在无网络环境下做端到端测试（`PuraMarkdown.Testing`）。
- **复用场景**：离线回放、日志查看器、导出报告、桌面单机版都需要"无 Agent"模式。
- **方案 4 不够**：把选择写回 Markdown 需要了解 Agent 的提示词格式，且丢失结构化信息。

## 后果

- 宿主需要实现 `IInteractionSink`（约 20 行）+ 自己的回传逻辑；库提供 `ToUserMessage()` / `ToJsonMessage()` 两种便捷形态（见语法规范 §6.4）。
- 无法开箱即用地对接某个 Agent 服务 → 通过"集成包"（如 `PuraMarkdown.Integrations.AGUi`）补齐，保持核心纯净。
- 幂等、状态机、过期等语义仍在库内，传输失败由宿主决定重试策略。
