# ADR-0015：流式采用「块级脏检查 + 尾部窗口 + 视觉树嫁接」

- 状态：已接受（取代 ADR-0004）
- 日期：2026-11-05
- 关联：架构 §9、需求 FR-501–509

## 背景

v0.2 方案：稳定块提交 + 尾部窗口重解析 + IR diff/patch。v0.3 取消 IR 后，diff 对象变为 Avalonia 控件；新需求方案提出"块级脏检查 + 增量嫁接"，并认为"只有最后一个块会变化"。

## 决策

采用三部分组合：

1. **块级脏检查**：每个顶层块维护 `BlockRecord { Hash, Start, End, Control }`；内容哈希不变则控件复用。
2. **尾部窗口重解析**（保留 v0.2 的正确性结论）：仅当尾部存在开放块（未闭合围栏/`pura-agent`、可能续接的列表/引用、未确认结束的表格）时，窗口内重解析；窗口默认 8–16 KB，绝不全文重解析。
3. **视觉树嫁接**：新块 → 追加控件；尾部块 → 优先 `IIncrementalPuraRenderer.Update`，否则替换该块控件；已提交块不动。

## 理由

- 提案的"只重解析最后一个块"在以下情况不成立：空行后列表/引用仍可续接、表格缺分隔行会退化、未闭合围栏需要继续累积。直接按"最后一个块"处理会产生内容错乱。
- 块级哈希是稳定、可测的脏检查依据，不依赖 Markdig 对象身份（AST 每次解析都是新对象）。
- 尾部窗口把每次追加的解析成本限制在 O(窗口) 而不是 O(文档)，Markdig 实测差距约两个数量级。
- 视觉树嫁接避免整棵树重建，保持滚动位置与交互状态。

## 后果

- 需要 `StreamingBlockScanner`（边界判定）与 `PuraStreamingSession`（状态机/合帧/线程）。
- 边界判定有误判风险：用"逐段追加 vs 一次性渲染 dump 等价"属性测试守住。
- 交互组件在流式完成前禁用，避免"选项未输出完就被点击"。
- 不提供重写/编辑（ADR-0010 仍然有效）。

## 备选

全文重解析 + 全树重建：实现最简单，作为调试开关保留（`StreamingOptions.ForceFullReparse`），不用于生产。
