## 2. 逐项修复

### P0-1：流式解析/渲染移出调用线程，UI 合帧

- `PuraStreamingSession.Append` 现在只做字符串入队 + 信号；后台 `WorkerLoopAsync` 负责解析、扫描、构建 `StreamingUpdate`。
- UI 线程通过 `Dispatcher.UIThread.Post` 应用更新；每次唤醒合并所有已到达增量，且一次最多应用一个更新（背压）。
- 新增 `PuraStreamingOptions.Synchronous`（测试/无 UI 循环的控制台场景）；GUI 默认异步。
- 新增 **会话令牌**（`SessionId`）：`Complete`/重置后，旧会话迟到的更新会被控件丢弃，避免串消息。
- Demo 的 `Reset` 会先 `AbortAsync` 再开新会话。

### P0-2：尾部块增量更新，不再整窗重建

- 尾部窗口按 **内容哈希 + 节点类型** 复用未变化前缀；只删除/更新变化的后缀。
- 新增 `IIncrementalPuraRenderer` 实现：段落、标题、代码块支持就地更新（代码块用 `Tag` 持有 `TextBlock`）。
- 修复了增量更新后控件未重新挂回宿主的问题。
- 稳定块仍只追加；尾部块不再每次 `RemoveTailRecords` + 全量重建。

### P0-3：重型渲染延迟 + 缓存

- **流式期间**：代码块高亮改为"后台预计算 span + UI 只建 Run"（追加优化，见 §6）；Mermaid 显示"生成中"占位、`pura-agent` 显示"准备中"占位；不执行图表引擎/JSON Schema。
- **Complete** 时一次全量渲染真实内容。
- 代码高亮按 `(language, codeHash)` 缓存；Mermaid ASCII 按 `sourceHash` 缓存，重复渲染/主题重建不再重算。
- 效果：长代码块流式 2977ms → 127ms；首次流式不再出现 CodeColor 正则编译造成的 90ms 尖峰（预热后）。

### P0-4：去掉每次 Append 的全量 `ToString()`

- 会话维护 `_full`（全文，仅 Complete 时 `ToString`）与 `_tail`（未提交窗口）。
- 每次只复制**尾部窗口**并只解析窗口；提交后从 `_tail` 前缀移除，`_committedOffset` 递增。
- 扫描器改为对尾部窗口从 0 扫描，不再每次扫全文。

### P1 配套：预热（直接缓解首次点击卡顿）

- 新增 `PuraMarkdownView.Prewarm(markdown)`：在离屏探针控件中完整渲染一遍代表性内容（代码/表格/图表/组件），把 JIT、正则编译、字体/样式初始化提前到启动阶段。
- Demo 在 `Opened` 时预热（表格 + 代码 + Mermaid + choice + rating）。
- 效果：Demo 首次流式 310ms → **13.8ms**。

## 3. 行为变化（需注意）

1. **流式期间**代码块已支持高亮（后台预计算，100ms 节流；超过 32KB 的代码块流式期显示纯文本）；Mermaid/交互组件仍显示占位，`Complete` 后呈现完整效果。
2. 异步会话的 `Append` 不再保证调用返回时已渲染；宿主界面会稍后合帧更新。
3. 需要"调用即渲染"的测试/控制台请显式使用 `new PuraStreamingOptions { Synchronous = true }`。
4. 超长未闭合块仍受 `TailWindowChars`（16KB）限制，超限时强制提交（Complete 全量校正兜底）。

新增测试：`Async_streaming_applies_intermediate_updates`（异步会话逐步显示）、`Async_streaming_completes_like_one_shot`（异步与一次性等价）、`Prewarm_renders_representative_blocks_without_side_effects`；共 71 个测试全部通过（含多轮消息规模回归、流式高亮与分帧 Complete）。

### 修复后补充：异步会话"只能最后一次性显示"

首轮验证发现：异步 worker 访问 `view.Options`（Avalonia 属性）时跨线程抛 `InvalidOperationException`，worker 静默失败，所有增量更新被丢弃，直到 `Complete` 才全量显示。

修复：
- 会话创建时在 UI 线程捕获 `PuraMarkdownOptions`，worker 只使用该快照做解析/清洗，不再触碰任何 Avalonia 对象；
- 新增 `LastWorkerError` 诊断属性；`Async_streaming_applies_intermediate_updates` 测试确保异步模式确实逐步渲染。

## 6. 追加优化：流式过程中高亮代码

### 实现

1. **后台预计算**：流式 worker 在解析窗口时，遍历 `CodeBlock`，用 `ICodeHighlighter` 计算 `HighlightSpan[]`，随 `StreamingWindowUpdate` 传给 UI；`RenderContext.PrecomputedHighlights` 按节点索引。
2. **UI 只生成 Run**：`CodeBlockRenderer` 在流式路径直接使用预计算 span，不再在 UI 线程调用 `Highlight()`。
3. **节流**：尾部代码块同一位置 100ms 内最多重算一次（或增长不足 256 字符时复用上一份前缀高亮），新增字符先以纯文本显示，下个刷新周期补齐；避免 16 字符/40ms 的追加把高亮算成 O(n²) 的 CPU 黑洞。
4. **上限**：单块 >32KB 时流式期不高亮，稳定/Complete 后一次性高亮，控制 UI Run 数量。
5. 高亮结果按 `(language, codeHash)` 缓存；提交块直接复用缓存。

### 复测（Debug，同步模式含后台计算）

| 场景 | 修复前（流式不高亮） | 现在（流式高亮） |
| --- | --- | --- |
| Demo 同款（2.5KB）首次 | 13.8ms / p95 1.1ms | 45ms / p95 4.8ms |
| 长代码块（14.3KB，896 次） | 127ms / p95 0.3ms | **177ms / p95 0.3ms** |

> 同步模式把后台计算也算在调用线程；GUI 默认异步模式下高亮在 worker 线程完成，UI 线程只承担 Run 生成。

新增测试：`Streaming_code_block_is_highlighted_before_complete`（同步）、`Async_streaming_highlights_code_before_complete`（异步后台高亮）。

## 7. 追加优化：Complete 分帧，消除长消息结束时的全量冻结

### 实现

- `CompleteAsync` 不再在 UI 线程同步全量解析：
  1. 后台线程 `PrepareDocument`：解析全文、清洗、**预计算所有代码块高亮 span**；
  2. UI 线程 `RenderPreparedAsync`：按"最多 16 块或 8ms 一帧"分批挂载控件，每帧 `DispatcherPriority.Background` 让出消息泵；
  3. 代码高亮直接使用后台 span，UI 不再调用 `Highlight()`。
- `Synchronous` 会话仍走原同步路径，保证测试/控制台确定性。

### 效果

| 指标 | 之前 | 现在 |
| --- | --- | --- |
| 1.8MB / 4800 块 Complete（异步路径） | 单次 UI 冻结约 445ms | 每帧 ≤8ms 挂载，无单次长冻结（墙钟总耗时相近） |
| UI 线程高亮计算 | Complete 时全量计算 | 后台完成，UI 只建 Run |

新增测试：`Async_complete_renders_large_document_in_chunks`（600 段异步 Complete，验证分帧路径无死锁/无丢块）。

## 8. 修复：流式提交块与旧尾部块重复显示

**现象**：流式代码块先显示部分内容（如 "va"），下一次刷新完整代码出现在第二个代码块，视图中同时存在两个代码块，直到 Complete 才恢复。

**根因**：一次更新同时包含"稳定块（刚闭合的代码块）"和"新尾部块"时，`ApplyStreamingUpdate` 先追加稳定块，再调用尾部替换；尾部替换按 `_records.Count - _tailRecordCount` 计算旧尾部范围，此时末尾已经是刚追加的稳定块，导致删错记录/控件，旧尾部代码块残留并与新块并存。

**修复**：应用稳定窗口前，先移除上一次的尾部记录/控件，再追加稳定块，最后应用新的尾部窗口。虚拟化模式同样生效。

**回归测试**：`Committed_block_replaces_streaming_tail_without_duplicate`——先追加不完整代码围栏，再追加闭合围栏 + 空行 + 段落，断言代码文本只出现一次、块数为 2。
