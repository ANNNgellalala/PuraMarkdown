# 块级虚拟化实现（2026-11-07）

> 目标：单条超长消息（1MB / 1000 块）不再一次性实例化全部块控件。采用可选 `ItemsRepeater` 模式，默认行为不变。

---

## 1. 使用方式

```csharp
var options = new PuraMarkdownOptions
{
    Pipeline = pipeline,
    EnableBlockVirtualization = true, // 默认 false
};

var view = new PuraMarkdownView { Options = options, Markdown = longText };

// 启用后控件自带 ScrollViewer，不要再外层包 ScrollViewer
window.Content = view;

// 流式追加后可跟随底部
view.ScrollToEnd();
```

- 默认 `false`：`StackPanel` 全量挂载，行为与旧版本一致；
- `true`：`ScrollViewer + ItemsRepeater + StackLayout`，只实例化视口内块；
- `Blocks` 元数据仍完整；虚拟模式下 `BlockRecord.View` 为 `null`（控件按需创建）。

---

## 2. 验证数据（无头，920×700 视口，1MB / 1000 块）

| 模式 | 块数 | 实例化 TextBlock | 打开耗时 | 内存 |
| --- | --- | --- | --- | --- |
| 默认 StackPanel | 1000 | **1000** | **2652ms** | **69.8MB** |
| `EnableBlockVirtualization` | 1000 | **4** | **455ms** | **1.6MB** |

> 打开耗时包含 Markdig 解析与首屏布局；内存为窗口/控件/块元数据增量（GC 后测量）。

复现：

```bash
dotnet run -c Release --project samples/PuraMarkdown.Spike -- --block-virtualization-perf
```

---

## 3. 流式支持

- 稳定窗口：追加虚拟条目；
- 尾部窗口：替换尾部条目，`ItemsRepeater` 只重渲染可见项；
- 代码高亮/组件仍使用后台预计算上下文；
- `Complete` 时用完整 `PreparedDocument` 重建虚拟集合（不再分帧挂载，因为只实例化可见块）。

测试：

- `Virtualized_view_realizes_only_visible_blocks`：500 段 → 实例化 1–100 个；
- `Virtualized_streaming_keeps_block_metadata_and_limits_controls`：流式 200 段 → 元数据完整、实例化受控。

---

## 4. 限制

| 限制 | 说明 |
| --- | --- |
| 外层滚动 | 启用后控件自带 `ScrollViewer`，宿主不要重复包裹 |
| 交互状态 | 视口外组件控件被回收，本地选择状态不保留；以 `InteractionOccurred` 事件为准 |
| 自动滚动 | 不自动；流式后可调用 `ScrollToEnd()` |
| 变高块 | 使用 `StackLayout` 实测高度，滚动条可能随估算修正轻微跳动（长消息可接受） |
| 包依赖 | 核心包新增 `Avalonia.Controls.ItemsRepeater`（Avalonia 官方包） |

---

## 5. 与消息级虚拟化的关系

| 层级 | 做法 | 解决 |
| --- | --- | --- |
| 消息级 | 宿主用 `ItemsRepeater` 承载多条 `PuraMarkdownView` | 1000 条历史的内存/布局（121MB → 2.9MB） |
| 块级 | 单条消息内部启用 `EnableBlockVirtualization` | 单条 1MB 消息的 70MB → 1.6MB、2.6s → 0.45s |

两者互补：长对话可同时启用。
