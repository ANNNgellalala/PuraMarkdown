# B 阶段实施记录（B0–B5）

> 日期：2026-11-08。B 方案已落地：Markdig AST 保持为语法契约，新增 `PuraMarkdown.Syntax` 与 `PuraDocumentView`，渲染层消费语法层产物。
> 关联：[B→C 演进路径](32-技术演进路径-B到C.md)、[ADR-0025](adr/0025-syntax-renderer-separation.md)。

## B0：契约与基线

- 公共契约：
  - `PuraSyntaxBuilder` / `PuraSyntaxPipeline`；
  - `PuraDocument`（`MarkdownDocument` + 版本 + 诊断 + 大纲）；
  - `IPuraNodeRenderer`（输入 `MarkdownObject`）；
  - `PuraDocumentView`。
- 决策：Markdig AST 作为 B 的语法契约，不复制节点；支持节点子集 + 版本锁定。
- 产出：ADR-0025、[技术演进路径](32-技术演进路径-B到C.md)。

## B1：`PuraMarkdown.Syntax`

- 新项目 `src/PuraMarkdown.Syntax`：
  - 只依赖 Markdig，无 Avalonia 引用；
  - `PuraSyntaxBuilder`：CommonMark/GFM/Markdown 扩展；
  - `PuraSyntaxPipeline.Parse` / `ParseDocument` / `ParseIncremental` 契约；
  - `PuraDocument`、`PuraDiagnostic`、`PuraOutline`、`PuraHeading`、`PuraFoldRange`；
  - `PuraSyntaxStreamingSession`（B 阶段语义等价，后续可下沉稳定边界）；
  - `StreamingBlockScanner` 从核心迁入 Syntax。

## B2：渲染层消费语法文档

- `PuraMarkdown` 引用 `PuraMarkdown.Syntax`。
- `PuraPipeline` 持有 `PuraSyntaxPipeline`；`Parse`/`ParseDocument` 委托。
- `PuraMarkdownView`：
  - 解析改由 Syntax 完成；
  - 新增 `RenderDocument(PuraDocument)`，不重新解析；
  - `GetOutline` 使用 `PuraDocument.Outline`。
- 新增 `PuraDocumentView`：接受已解析 `PuraDocument` 的渲染宿主。
- 新增 `IPuraNodeRenderer`；`IPuraRenderer` 作为兼容别名。
- Arc 风格自定义 renderer 可通过 `UseRenderer(priority)` 覆盖节点。

## B3：流式扫描迁移

- `StreamingBlockScanner` 归 Syntax；
- `PuraStreamingSession` 仍作为 UI 流式会话（负责渲染/高亮/状态）；
- `PuraSyntaxStreamingSession` 提供语法层流式入口；
- 现有增量/中断/重复完成测试保持通过，并补充了重复 Finish 的幂等测试。

## B4：Arc.Avalonia 集成验证

- 新增 `samples/PuraMarkdown.ArcSample`：只引用 Syntax，解析并输出大纲/节点；
- 测试 `SyntaxRenderingSeparationTests`：
  - 无 Avalonia 的语法解析/大纲；
  - `PuraDocumentView` 渲染预解析文档；
  - Arc 风格自定义 `IPuraRenderer` 覆盖 Heading。
- 结论：Arc 可只依赖 `PuraMarkdown.Syntax` + Markdig 消费语法树。
