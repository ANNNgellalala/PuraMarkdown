# 版本与升级策略（APP 迭代参考）

## 1. 版本号

- 当前：`0.1.0-alpha.1`；所有包**统一版本**（`Directory.Build.props`）。
- 0.x alpha 阶段允许破坏性变更；1.0 后按 [SemVer](https://semver.org/lang/zh-CN/)：
  - MAJOR：公共 API 不兼容；
  - MINOR：新增能力，向后兼容；
  - PATCH：修复，向后兼容。

## 2. 包版本矩阵

| 包 | 依赖 |
| --- | --- |
| `PuraMarkdown.Syntax` | Markdig 1.5.1（无 Avalonia） |
| `PuraMarkdown` | `PuraMarkdown.Syntax`、Avalonia 12.1.5、ItemsRepeater 12.0.0 |
| `PuraMarkdown.Agent` | 核心 + JsonSchema.Net 9.6.0 |
| `PuraMarkdown.Chat` | 核心 + ItemsRepeater |
| `PuraMarkdown.Highlighting.ColorCode` | 核心 + ColorCode.Core |
| `PuraMarkdown.Diagrams.Mermaid` | 核心 + Mermaider |
| `PuraMarkdown.Testing` | 核心 |

宿主升级时必须**同时升级**核心与所用插件，不要混用版本。

## 3. API 稳定性分级

| 级别 | 承诺 |
| --- | --- |
| 宿主 API（View/Options/Streaming/Events/Theme/Localizer/Limits） | 1.0 后稳定，破坏需 MAJOR |
| 插件 API（IPuraPlugin/Renderer/Inline/Fence/Highlighter/Sanitizer/Agent 组件） | 1.0 后稳定 |
| 高级（RenderContext、BlockRecord、Markdig 扩展） | 尽量兼容，不承诺 |
| 内部（默认渲染器、扫描器） | 随时调整 |

详见 [公共 API 参考](28-公共API参考.md)。

## 4. APP 升级步骤

1. 阅读 [迁移指南](27-迁移指南-0.1.0-alpha.1.md) 的 Breaking 列表；
2. 所有 PuraMarkdown 包统一到同一版本；
3. 编译后按错误逐项替换旧 API；
4. 跑 Markdown/Agent/流式/主题用例；
5. 如使用自定义插件，确认已实现 `IFenceRenderer`/`IPuraInlineRenderer`；
6. 更新锁文件/本地源缓存。

```bash
dotnet list package | findstr PuraMarkdown
dotnet restore
dotnet build
```

## 5. 发布前检查（库维护者）

- `dotnet build PuraMarkdown.slnx` 0 警告；
- `dotnet test` 全绿；
- `dotnet pack -c Release` 7 个包；
- README/迁移/API 参考更新；
- 打 tag 并更新 CHANGELOG；
- 1.0 前补充 `PublicAPI.Shipped.txt` 与分析器。

## 6. 兼容性策略

- 新增 API 优先（默认参数/新类型），少改旧签名；
- 删除/重命名先标记 `[Obsolete]` 一个 MINOR 周期（1.0 前可直接删除）；
- 插件契约变更需同时更新官方插件与示例；
- 文档中的示例必须与当前包版本一致。
