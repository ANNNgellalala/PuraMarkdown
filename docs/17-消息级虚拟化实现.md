# 消息级虚拟化实现（2026-11-07）

> 目标：解决长对话"历史消息全部保留控件"导致的内存与布局成本。基于 [多轮长对话性能验证](16-多轮长对话性能验证.md) 的结论，采用 `ItemsRepeater + StackLayout` 做消息级虚拟化。

---

## 1. 实现

### 核心复用方式

每条消息仍是一个独立的 `PuraMarkdownView`，但历史列表由 `ItemsRepeater` 虚拟化：

```csharp
var repeater = new ItemsRepeater
{
    ItemsSource = messages, // ObservableCollection<ChatMessage>
    ItemTemplate = new FuncDataTemplate<ChatMessage>((message, _) => new PuraMarkdownView
    {
        Options = options,
        Markdown = message.Markdown,
    }),
};
repeater.Layout = new StackLayout();

var scroll = new ScrollViewer { Content = repeater };
```

- 只实例化视口内（及少量缓存）的消息控件；
- 滚动时回收/重建消息视图；
- 追加新消息后 `ScrollToEnd()` 自动到底部。

## 2. 验证数据（无头，920×700 视口）

| 方案 | 消息数 | 实际实例化视图 | 块数 | 内存 |
| --- | --- | --- | --- | --- |
| 全部保留（场景 A） | 1000 | **1000** | 6000 | **121.2MB** |
| `ItemsRepeater` 虚拟化 | 1000 | **4** | 24 | **2.9MB** |

说明：realized 数量取决于视口高度、消息高度与滚动位置；该数据用于证明内存与控件数量不再随历史线性增长。

复现：

```bash
dotnet run --project samples/PuraMarkdown.Spike -- --virtualization-perf
```

Demo 运行：

```bash
dotnet run -c Release --project samples/PuraMarkdown.Demo/PuraMarkdown.Demo.csproj
# 点击工具栏 "长对话 (1000)"，观察状态栏 realizedViews 远小于 messages
```

## 3. 使用建议（聊天宿主）

1. **历史消息**：使用 `ItemsRepeater`（或等价虚拟化列表），每条消息一个 `PuraMarkdownView`，不要累积成单篇 Markdown。
2. **正在流式的消息**：建议放在列表外固定底部（或列表最后一项的独立控件），流式完成后再 `Add` 到消息集合；避免虚拟化回收正在流式的视图。
3. **自动滚动**：仅当用户已在底部时自动 `ScrollToEnd()`，避免打断向上阅读。
4. **超长单条消息**：仍建议折叠/延迟渲染；消息级虚拟化解决的是"多轮历史"，不解决单条 1MB 消息的块级布局成本。

---

## 4. 依赖与兼容

- 引入 `Avalonia.Controls.ItemsRepeater` **12.0.0**（与 Avalonia 12.1.5 兼容）。
- 仅示例/测试引用；核心 `PuraMarkdown` 包不新增依赖。
- 宿主可继续使用 `ListBox`/自定义虚拟化容器，只要满足"每条消息独立 `PuraMarkdownView`"。
