## 1. 基准（BenchmarkDotNet 0.15.8，本机 i7-12700F / .NET 10.0.14）

| 基准 | Mean | 分配 |
| --- | --- | --- |
| `Parse20Kb`（20KB 纯段落） | **7.4 µs** | 8.7 KB |
| `Parse1Mb`（1000 段 × 1KB） | **409 µs** | 534 KB |
| `FindStableBoundary`（扫描 12KB 文档） | **5.9 µs** | — |
| 8KB 尾部窗口解析（混合 Markdown：强调/行内代码） | **130–290 µs** | 207 KB |

结论：
- 1MB 解析远低于 NFR-06（≤150ms）目标；
- 尾部窗口解析 < 1ms，满足流式帧预算；
- 注意：`Parse20Kb` 是纯文本段落，含大量行内语法的文档解析更慢（8KB ≈ 130–290µs），性能目标按真实语料校准。

运行方式：

```bash
dotnet run -c Release --project benchmarks/PuraMarkdown.Benchmarks -- --filter '*Parse*'
dotnet run -c Release --project benchmarks/PuraMarkdown.Benchmarks -- measure   # 快速测量
```

## 2. 裁剪与 Native AOT

| 方式 | 结果 |
| --- | --- |
| `PublishTrimmed=true`（`TrimMode=link`） | 成功；裁剪后二进制运行正常，输出与未裁剪一致 |
| `PublishAot=true` | **成功**；产物 ~20MB，可直接运行并输出控件树 dump |

命令：

```bash
dotnet publish samples/PuraMarkdown.Spike -c Release -p:PublishTrimmed=true -o artifacts/trim-spike
dotnet publish samples/PuraMarkdown.Spike -c Release -p:PublishAot=true -o artifacts/aot-spike
```

> AOT 依赖本机 C++ 工具链；CI 默认只做 build/test/pack，AOT 作为手动/发布前检查。

## 4. API 文档（已完成）

- 四个发布包（核心 / Testing / ColorCode / Mermaid）均启用 `GenerateDocumentationFile`，生成 XML 文档。
- **CS1591 已从抑制改为启用，构建 0 警告**：所有公开可见类型与成员均有 XML 注释。
- 关键 API（控件、选项、管道、渲染上下文、Agent 模型、流式、安全）为人工撰写的说明；其余成员为简洁摘要，可在后续版本逐步丰富（不影响文档完整性）。
- 公开 API 面已收敛：默认渲染器/事件组件控件改为 `internal`，减少不必要的公共契约与 SemVer 负担。
