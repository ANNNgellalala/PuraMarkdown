# 需求对齐与设计复审（v0.4）

> 输入：用户新增的 [`PuraMarkdown需求方案.md`](PuraMarkdown需求方案.md)（下称"提案"）、上一版设计（v0.2，IR + 多平台适配）、2026-11-05 两轮决策（5 项 + 6 项确认 + IR/虚拟树/适配层专项讨论）。
> 结论：**提案的方向整体采纳**，v0.2 的"UI 无关 IR + 虚拟渲染树 + 适配器"被替换为 **Markdig AST 直连 Avalonia 控件**；扩展语法主路径由 `:::` 容器改为 **`pura-agent` 围栏 + JSON**；目标框架改为 **net10.0**，依赖取当前最新稳定版。IR/虚拟树/适配层**不进入 1.0**，改为预留钩子 + 触发条件（见 [`07`](07-IR-虚拟渲染树-多平台-讨论与决策.md)）。

---

## 1. 结论摘要

| # | 议题 | 结论 |
| --- | --- | --- |
| 1 | 渲染架构 | **采纳提案**：四层（解析路由 → 节点分发 → 渲染执行 → 流式会话），渲染器直接消费 Markdig 节点并产出 Avalonia `Control`；**取消** v0.2 的 IR、RenderNode 虚拟树、适配器分层 |
| 2 | 平台 | 1.0 是 **Avalonia 原生控件**，不做平台抽象层；多平台后置（若未来需要，再抽契约，见 ADR-0016） |
| 3 | 扩展语法 | **采纳提案**：`pura-agent` 围栏 + JSON 为主路径；`:::` 容器指令降级为**插件可选的语法扩展** |
| 4 | 插件契约 | **采纳提案**：`IPuraRenderer`（`CanRender` + 返回 `Control`）、`IAgentComponentParser`、`IAgentComponentRenderer`、`IDiagramRenderer`、`IPuraPlugin`、`PuraPipelineBuilder` |
| 5 | 交互 | 采纳提案：控件内维护选择状态，通过事件上报；库不管理对话、不发消息（与 v0.2 一致） |
| 6 | 图表 | 采纳提案：核心**只识别围栏**并路由给 `IDiagramRenderer` 插件；**放弃 v0.2 的 `ChartSpec` 核心契约**（与之前"核心定义 ChartSpec + ScottPlot"的决策冲突，需你裁决，见 §6-Q4） |
| 7 | 流式 | 采纳提案的"块级脏检查 + 增量嫁接"，但**保留 v0.2 的关键正确性结论**：尾部窗口重解析、未闭合围栏容忍、追加等价性属性测试 |
| 8 | 框架/依赖 | **net10.0** 单目标（本机 SDK 10.0.114）；Avalonia 12.1.5、Markdig 1.5.1 等全部取最新稳定版（§5 版本基线） |

## 2. 提案要点（作为对齐输入）

1. 只读渲染宿主：消费 Markdown 文本，输出 Avalonia 原生视觉树；无源码编辑、无源码位置映射。
2. Markdig 只负责标准 Markdown 解析；PuraMarkdown 通过自定义 `BlockParser`/`InlineParser` 识别 Agent 扩展语法，产出混合 AST。
3. 节点分发是插件化核心接缝：按节点类型查注册表，命中插件渲染器，否则回退基础默认渲染器。
4. 渲染器接收 Markdig 节点 + 上下文，产出 Avalonia `Control`；默认渲染组（段落/标题/列表/引用/表格/代码块/链接/图片）以**低优先级注册项**存在，可被覆盖。
5. Agent 交互组件是一等公民：`pura-agent` 围栏 + JSON → `PuraAgentBlock`；单选/多选渲染为原生控件，选择通过事件上报。
6. 流式：块级脏检查 + 增量嫁接；未闭合围栏显示占位；`Append` 线程安全，解析/diff 后台、嫁接 UI 线程。
7. 图表：核心只识别围栏（` ```mermaid `、` ```pura-chart `），渲染交给 `IDiagramRenderer` 插件，无插件时回退代码块。
8. 错误分层降级：组件解析失败显示源码 + 首条错误；插件渲染异常回退默认渲染器；流式不完整不算错误。
9. 明确不做：编辑、源码映射、对话状态、Agent 通信、内置图表引擎、内置语法高亮引擎。
10. 落地顺序：解析路由+基础渲染 → `pura-agent`+choice → 插件机制（高亮/图表）→ 流式会话。

## 3. v0.2 → v0.3 差异对照

| 维度 | v0.2 设计 | 提案（v0.3 采纳） | 取舍理由 |
| --- | --- | --- | --- |
| 文档模型 | 自建不可变 IR（`PuraDocument`/`PuraNode`） | **Markdig AST 即模型**，不另建 IR | 少一层转换与映射；只读场景不需要跨平台/序列化 IR；渲染器直接消费熟悉的 Markdig 类型，插件门槛低 |
| 渲染中间层 | `RenderNode` 虚拟树 + diff patch | **直接产出 Avalonia `Control`**，块级增删/替换 | 少一层映射与同步；Avalonia 视觉树本身就是最终产物，块级粒度的"重建/更新"已够用 |
| 平台 | 核心零 UI 依赖 + 多适配器 | **Avalonia 原生**，单平台 | 1.0 目标就是 Avalonia 桌面；多平台抽象的成本在只读场景不划算 |
| 扩展语法 | `:::` 容器为主，围栏 JSON 为兼容 | **`pura-agent` 围栏 JSON 为主**，容器指令为插件 | 对 Markdig 负担最小；JSON schema 可独立演进；Agent 生成围栏比嵌套容器更稳；降级为代码块最干净 |
| 插件契约 | `IComponentDescriptor` + 载荷绑定 + 适配器渲染器 | **`IPuraRenderer` 直接按节点类型匹配** | 契约更窄、组合更直观；组件语义收敛到 `IAgentComponentParser` |
| 交互 | 事件 + 建议文本；状态机在渲染会话 | 事件转发，控件内部维护选择状态 | 一致；更贴近 Avalonia 控件实践 |
| 图表 | 核心 `ChartSpec` + ScottPlot/CSharpMath | **`IDiagramRenderer` 外置契约**，核心不定义图表数据模型 | 图表引擎差异大、演进快，核心不该背 schema；插件可自带 `pura-chart` schema |
| 高亮 | 适配器内置选型 | **`ICodeHighlighter` 注入**，默认纯等宽 | 与提案一致；默认零依赖、可替换 |
| 流式 | 稳定块提交 + 尾部窗口 + IR diff | **块级脏检查 + 视觉树嫁接**（保留尾部窗口与等价性测试） | 提案的简化正确，但"只重解析最后一个块"过于乐观：列表/围栏/容器可跨块，必须保留稳定边界判定 |
| 安全 | IR 层集中过滤 | 解析期 `DisableHtml` + 渲染期 `IUrlPolicy`/`IImageLoader` | 无 IR 后过滤点前移到解析与渲染两处，需显式约定（见架构 §11） |
| 测试 | IR golden + HTML 导出快照 | **无头 Avalonia 视觉树 dump 快照** + 解析测试 + 追加等价性 | 无 IR 后以"控件树语义 dump"作为确定性基线 |
| 框架/依赖 | net8.0 | **net10.0**（SDK 10.0.114） | 用户要求；Avalonia 12.1.5 提供 net10.0 资产 |

## 4. 被放弃/降级的能力（及影响）

| 能力 | 状态 | 影响与补偿 |
| --- | --- | --- |
| UI 无关 IR | **取消** | 失去"IR 快照/跨平台渲染/独立导出"的天然入口；补偿：保留 `MarkdownObject` 遍历工具与"文本/HTML dump"（仅测试与复制），不承诺跨平台 |
| 多平台适配器 | **取消（后置）** | 核心直接引用 Avalonia；未来若需多平台，需抽 `IPuraRenderer` 的平台无关版本（成本见 ADR-0016） |
| 核心 `ChartSpec` | **取消** | 图表 schema 归插件；核心只做围栏路由与回退。之前"ScottPlot + CSharpMath 进核心"的决策失效（需你确认） |
| `:::` 容器语法 | **降级为插件** | 基础包只支持 `pura-agent` 围栏；若需要容器语法，插件注册 `BlockParser`（成本低，提案明确允许） |
| HTML 子集 | **维持禁止** | 与 ADR-0009 一致；`DisableHtml` + 转义展示 |
| 编辑/源码映射 | **维持不做** | 与提案一致 |
| 渲染树 patch/diff 抽象 | **取消** | 用 Avalonia 原生视觉树增删替换；块级粒度 + `IIncrementalPuraRenderer` 覆盖需要优化的场景 |

## 6.5 IR / 虚拟渲染树 / 多平台适配：讨论结论（2026-11-05）

结论（**已确认，2026-11-05 选项 A**）：**三项都不进入 1.0 实现计划**，改为"预留钩子 + 触发条件"（详见 [`07-IR-虚拟渲染树-多平台-讨论与决策.md`](07-IR-虚拟渲染树-多平台-讨论与决策.md) 与 ADR-0020/0021/0022）。

| 部分 | 1.0 | 触发条件（满足才加） | 回补成本 |
| --- | --- | --- | --- |
| IR | 不做；Markdig AST + `IAstSanitizer` 净化 pass | 非 Avalonia 后端 / 服务端渲染 / 节点级缓存 / Markdig 无法适配的 breaking | 3–4 周 |
| 虚拟渲染树 | 不做；`BlockRecord` + 块级嫁接 | 多后端 / 块内超长内容 / 渲染结果序列化 | 2–3 周 |
| 多平台适配层 | 不做；Avalonia 跨平台 + 薄服务接口 | Blazor/MAUI/非 Avalonia 宿主 / Avalonia 平台限制 | 3–4 周 |
| 预留钩子 | 做（约 2–3 人日） | — | — |

> 若未来计划 2.0 多后端，建议只先加 IR（双轨演进），虚拟树与适配层仍等真实需求。

## 7. 保留自 v0.2 的资产（仍然有效）

1. **Markdig 技术调研**（`research/markdig.md`）：无增量解析、`UsePreciseSourceLocation`、`DisableHtml` 不过滤 URL scheme、`:::` 容器语义、性能基线——v0.3 仍全部适用。
2. **流式正确性结论**：尾部窗口重解析（8–16KB）、稳定边界判定、未闭合围栏容忍、追加等价性属性测试。
3. **安全决策**：不渲染 HTML（ADR-0009）、URL scheme 白名单、交互回传白名单、零网络默认。
4. **append-only 流式语义**（ADR-0010）：无编辑/重写/续写。
5. **交互事件契约**（ADR-0006）：库只产事件，传输归宿主。
6. **生态调研**（`research/ecosystem.md`）：版本、许可证、A2UI/json-render 等参考。

## 8. 风险清单（v0.3 新增/变化）

| # | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| N1 | Markdig AST 是解析器内部模型，跨版本不稳定 | 插件与核心强耦合 Markdig 版本 | 锁定 1.5.1；核心只消费公开节点类型；升级过回归套件 |
| N2 | 无 IR → 无集中过滤点 | 安全策略可能漏配 | 解析期固定 `DisableHtml`；渲染期强制 `IUrlPolicy`/`IImageLoader`；默认渲染器内置转义；安全用例集 |
| N3 | 无 IR → 无法做 IR 级 golden 测试 | 回归定位变难 | 无头视觉树 dump 快照 + 解析断言 + 属性测试；测试工具独立包 |
| N4 | "只重解析最后一个块"在列表/围栏/引用下不成立 | 内容错乱/重复 | 稳定边界扫描（尾部窗口）+ 等价性属性测试（见架构 §9） |
| N5 | 插件渲染器在 UI 线程抛异常 | 整条消息崩溃 | 渲染隔离 + 回退链 + 非致命 warning 事件 |
| N6 | 交互控件状态与重渲染冲突（追加导致控件重建，选中丢失） | 交互体验差 | 交互组件在流式完成前禁用；重渲染保留组件实例（`IIncrementalPuraRenderer`）或按实例 ID 复用 |
| N7 | Avalonia 12 API 演进/Breaking | 维护成本 | 锁定 12.1.5；适配层集中在少量控件工厂 |
| N8 | 图表/高亮插件体积与许可证 | 分发问题 | 插件独立 NuGet；核心里程碑不含引擎；许可核验（MIT/Apache/BSD） |
